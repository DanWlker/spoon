Common tasks, step by step

The keys for what you do most, one step at a time. Whenever a key slips your mind, ? lists the actions of the panel you're on: /, type a few words, Enter, Enter runs it. See the panels for where things are and the keymap for every key.

Stage some lines and commit

  1. Tab to the local changes page, j/k to the fileThe diff of the selected file shows on the right.
  2. Enter selects its hunks, Enter again the lines of oneOr Space on the file to stage all of it, or on the / row at the top to stage everything.
  3. v, j to select lines, Space stages them

  4. c commitsWith no message yet, it starts typing the summary: Enter goes on to the description, Esc stops. c again shows the commit to make; Enter makes it.

Squash a few commits

  1. On the graph, v on the newest, j down to the oldestThe picked commits are marked; Esc clears them.
  2. s squashes them into their parentsThe popup asks how to combine the messages and shows the git command; Enter runs it.

Rebase, and get through a conflict

  1. r on the commit to rebase onto, EnterOn a conflict the local changes page opens.
  2. Enter on a conflicted file, h/l picks a side, Space keeps itOr open it in your merge tool or editor from the conflict panel. The file is staged once resolved.
  3. m shows what you can do with the rebase
    Unstaged ╭ Keys ───────────────────╮ │ a ➜ abort │ │ c ➜ continue │ │ s ➜ skip │ ╰─────────────────────────╯
  4. c continuess skips the commit it stopped at, dropping its changes; a goes back to where it started. Both ask first. A merge, cherry-pick or revert is finished with c, committing, and m a aborts it.

Walk through a big change folder by folder

  1. In the files of the local changes page, ] FGoes to the next folder at the same depth, over the folders inside, a level up when none is left; [ F goes back. ] f goes file by file.
  2. From the diff, ] F stays in the diffShowing the first file of the next folder.

Copy a hash, a path or a link

  1. yA popup lists what can be copied there: y the short hash (a relative path on a file, a name on a ref), f the full one, l the link on GitHub, GitLab and the like.
  2. In a diff or the lines of a file, y copies the selected lines at onceY copies their link.

Find an action you don't remember

  1. ? opens the keys listThe actions of the panel you're on first, with their keys, then those of the other panels, dimmed.
  2. /, type gitignore, EnterOnly the matching actions stay.
  3. Enter runs the selected oneActions with no key run from here too.
